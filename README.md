# javascript-calculator-precourse

- [x] 입력한 문자열에서 숫자를 추출하여 더하는 계산기를 구현한다.

  - [x] 쉼표(,) 또는 콜론(:)을 구분자로 가지는 문자열을 전달하는 경우 구분자를 기준으로 분리한 각 숫자의 합을 반환한다.
    - [x] 빈 문자열 0으로 변환
      - [X]"" => 0
    - [x]"1,2" => 3
    - [x]"1,2,3" => 6
    - [x]"1,2:3" => 6
  - 내가 찾은 예외 및 예시
    - [x] 커스텀 구분자 없는 경우 //\n -> 기본 구분자로 분리
    - [x] 공백 포함 -> ERROR
      - [x] "1,2 " => ERROR
    - [x] 분리한 문자가 숫자가 아닌 경우 -> ERROR
    - [x] 음수,0 -> ERROR
    - [x] 1,,2 와 같이 구분자의 개수 != 숫자 개수 -1 -> ERROR

- [x] 앞의 기본 구분자(쉼표, 콜론) 외에 커스텀 구분자를 지정할 수 있다.

  - [x] 커스텀 구분자는 문자열 앞부분의 "//"와 "\n" 사이에 위치하는 문자를 커스텀 구분자로 사용한다.
  - [x] 예를 들어 "//;\n1;2;3"과 같이 값을 입력할 경우 커스텀 구분자는 세미콜론(;)이며, 결과 값은 6이 반환되어야 한다.
  - [x] //\n 와 같이 커스텀 구분자가 빈 문자열인 경우 추가하지 않는다.

- [x] 사용자가 잘못된 값을 입력할 경우 "[ERROR]"로 시작하는 메시지와 함께 `Error`를 발생시킨 후 애플리케이션은 종료되어야 한다.

## 어려웠거나 고민되었던 점:

1. 검증을 다 하고 값을 알맞은 형태로 변환시킬지? 아니면 값을 변환시키고 검증을 할지?
2. 정규표현식 이용해서 만드는 데 오래 걸렸다. -> RegExp를 새로 만들 때는 다시 이스케이프 해줘야함.
3. 메소드 10줄 제한으로 해봤는데 줄을 줄이기 어려웠다.
   1. 함수나 변수를 어디부터 어디까지 묶을지가 고민이다. 같은 관심사만 묶어서 분리했다고 생각하는데 그래도 10줄이 딱 맞는 경우가 있었다.
4. validation 을 어떻게 처리하면 좋을지 고민이다.
   1. 함수로 할지 클래스로 설정해서 할지.
   2. 어디서 처리할지도 고민이다. input(view) 받는 곳에서 할지 아니면 컨트롤러에서 할지
5. 사용자 입력(input)을 가공해서 (ex: 이스케이프 처리) 사용해야할 때가 있는데 이걸 컨트롤러에서 검증이 끝난 후에 컨트롤러에서 가공시켰다. 이게 맞는 방식일까?

## 순서

1. 테스트 코드 통과까지 시간 얼마나 걸린지
   1. 기본적으로 3시간~ 3시간 반 걸린 것 같다. 그러나 추후에 리팩토링 하면서, 소수를 고민하지 않고 정수만 생각한 경우 등을 고치고, 코드 분리하는데 걸린 시간까지 다 하면 4시간~5시간 걸린 것 같다.
2. 4시간 어떻게 활용했는지

   1. 요구사항 먼저 확인 후 리드미에 기능 구현 뭐 할지 작성
   2. 예외 경우 뭐 있을지 고민 후 리드미에 추가적으로 계속 작성
   3. 테스트 코드 짜보면서 단위 테스트 시도해봄 -> 구현하다 보니 어느 순간 흐름 잃고 많이 작성할 때 있었음
   4. View.js에 Input과 Output 모듈 작성
   5. App.js에 거의 다 작성하고 그 다음에 모듈화 시킴.

3. 코드 흐름 설명
4. 코드를 짜면서 어려웠던 부분이나 고민되던 부분, 추후에 고치고 싶은 부분
5. 상대방 잘한점 1가지, 아쉬운점 1가지

### 좋았던 점

- 템플릿 만들어두고 복붙해서 쓰면 시간이 많이 단축됨
  - mvc 패턴 + constant, util, validation
  - 구조가 반복되므로 미리 만들어두면 시간이 매우 단축될 것 같음.
  - 경로가 같으므로 import 이후도 신경 쓸 필요가 없음.

### 아쉬운 점

- 검증에서 커스텀 구분자와 일반 구분자 중복되는 부분이 있는 것 같다.
  - 5개를 지우고 일반 구분자 처리하듯이 하면 될 것 같다.
